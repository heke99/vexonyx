# Security Policy

Security reports for VEXONYX should be handled privately and responsibly.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for a suspected security vulnerability.

Send the report privately to **info@vexonyx.com** with a subject beginning with `[SECURITY]`.

Include, when available:

- the affected VEXONYX component or route;
- the commit, version, or environment you tested;
- clear reproduction steps;
- the observed and expected behavior;
- the potential security impact;
- relevant logs, request IDs, screenshots, or minimal proof-of-concept material that does not expose third-party data or secrets;
- any suggested remediation.

## Responsible testing

Only test systems, accounts, tenants, data, infrastructure, or targets that you own or are explicitly authorized to test.

Do not:

- access, alter, retain, or disclose data belonging to other users or organizations;
- degrade service availability;
- perform destructive testing against production;
- exfiltrate secrets or personal data beyond the minimum evidence required to demonstrate a vulnerability;
- publish vulnerability details before coordinating disclosure with VEXONYX.

If a vulnerability can be demonstrated without accessing sensitive data or causing damage, use that safer method.

## Scope

This policy covers security issues in the VEXONYX application and repository maintained by this project. Vulnerabilities in third-party services should normally be reported to the relevant provider unless the issue is caused by VEXONYX's integration or configuration.

## Disclosure

We ask reporters to keep vulnerability details private while the issue is being investigated and remediated. Public disclosure should be coordinated after a fix or mitigation is available.

This policy does not grant authorization to test third-party systems or to exceed permissions granted by a VEXONYX account, engagement, or other written authorization.
